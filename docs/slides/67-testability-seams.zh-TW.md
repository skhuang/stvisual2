## 什麼讓程式碼無法被測試

一個單元之所以無法被測試，是因為測試無法**控制它的輸入**或**觀察它的輸出**。最常見的原因是**寫死的相依（hard-coded dependency）**：程式碼自己伸手去抓一個協作者，於是沒有任何測試能把另一個放到它的位置。

留意這些洩漏底細的形狀：

- 讀取**全域或單例（singleton）**——一個測試無法設定的隱藏輸入，
- 對一個具體協作者做 **`new`**——一個測試無法替換的相依，
- 呼叫**真實時鐘**——一個測試無法釘住的值，
- 呼叫**真實亂數（RNG）**——一個測試無法使其具決定性的值。

以上每一個都把一個真實相依**釘死**進函式體。受測行為於是與真實世界糾纏在一起，單元測試沒有任何接縫可以伸手進去。

<!-- 把整份投影片扣回本章節稍早的可控制性／可觀察性框架：寫死的相依是可控制性的失敗——你無法餵給單元你想要的輸入。強調這四個都不是 bug；程式碼跑得正確。它們是恰好使程式碼對測試充滿敵意的*設計*選擇。這裡的四個形狀與後面幾張投影片中受測片段的四個反樣式一一對應，所以要精確點名。 -->

## Feathers 的接縫概念

Michael Feathers（《Working Effectively with Legacy Code》）給了關鍵詞彙：**接縫（seam）**是一個你可以**不在該處編輯就改變程式行為**的地方——你從外部、透過接縫改變它。

每一道接縫都有一個**啟用點（enabling point）**：你在此選擇要跑哪個行為的位置。對於**物件接縫（object seam）**，啟用點是一個參數或欄位——呼叫者決定要傳入哪個物件,受測程式碼就使用它被交到手上的那一個。

這正是本講整個設計動作：把每一個寫死相依變成一道**物件接縫**,讓測試能在啟用點交入一個替身，而不是真的那一個。

<!-- 仔細定義接縫——學生常把它與「重構」或「介面」混為一談。接縫特指一個行為替換的點，*外加*一個選擇該行為的啟用點。Feathers 編列了好幾種（前處理接縫、連結接縫、物件接縫）；本講只用物件接縫，因為在一個有參數與欄位的語言裡，它最乾淨且不需要建置系統的花招。物件接縫的啟用點就是「你傳入的引數」——保持這麼具體。 -->

## 無法被測試的 `charge()`

```js
function charge(amount) {
  const cfg = Config.instance();          // 讀取全域單例
  const gw  = new PaymentGateway();        // 寫死的 new
  const at  = Date.now();                  // 真實時鐘
  const id  = Math.random().toString(36);  // 真實亂數
  return gw.charge(cfg.merchant, amount, at, id);
}
```

四個相依、四個反樣式，全都釘死在函式體裡。一個呼叫 `charge(100)` 的測試，拿到的是**真實**的 config、**真實**的 gateway、**牆上時鐘**的時間，以及一個**隨機**的 id——沒有一個是它選的，也沒有一個是它能拿來檢查的。

可測試性儀表讀作 **0/4**：這裡還沒有任何東西可被替換。

<!-- 這是本講其餘部分操作的樣本——它正是接縫探索器所渲染的片段（元件中的 CODE_FRAGMENTS）。走過這四行，把每一行連到上一張投影片的反樣式形狀。指出這個函式*能運作*——它確實刷了卡——這正是為什麼在審查時很容易漏掉它的不可測試性。0/4 儀表就是探索器的可測試性分數 = 已套用修正 / 4；接下來每一張投影片都把它往上推一格。 -->

## 修正 1 — 全域單例 Config → 注入 config

```js
// 之前                                 // 之後
const cfg = Config.instance();         function charge(deps, amount) {
                                       const cfg = deps.config;
```

讀取全域是一個**隱藏輸入**：`Config.instance()` 伸進了測試從未選擇的共享狀態。把 `config` 當成 `deps` 的一部分傳入，就把它變成一道**物件接縫**——測試在啟用點提供自己的 config。

- **接縫型別：** 物件接縫
- **可啟用（替身）：** **stub（樁）**——一個帶有測試所要的確切值的現成 config
- **解鎖能力：** *不動全域即可提供測試用的設定*

儀表 → **1/4**。

<!-- 這裡的 stub 是一個只回傳固定資料的測試替身——一個帶有已知商家 id 的 config 物件。重點是測試不再需要去改動全域狀態（那會在測試之間洩漏並強加執行順序）來架設它的情境。這是物件接縫最單純的形式：把一次全域查找換成一個參數。保持反樣式 → 接縫 → 替身的對應精確：讀取全域 → 物件接縫 → stub。 -->

## 修正 2 — 寫死的 `new PaymentGateway()` → 注入協作者

```js
// 之前                                 // 之後
const gw = new PaymentGateway();       const gw = deps.gateway;
```

那個 `new` 把一個具體協作者**焊進** `charge()`：每一個測試都會打到真的付款 gateway。把 gateway 當成協作者注入（藏在介面之後）使它成為一道**物件接縫**——測試交入它所需要的那個 gateway。

- **接縫型別：** 物件接縫
- **可啟用（替身）：** **mock（模擬）**——一個記錄呼叫、且可被指示失敗的 gateway
- **解鎖能力：** *強制 gateway 失敗*

儀表 → **2/4**。

<!-- 這是經典的「new 就是膠水」問題——直接呼叫建構子是最難打破的相依，因為它點名了一個具體型別。藏在介面之後注入就是修正。替身是 *mock*，因為這裡有趣的測試是關於*互動*的：charge() 是否以正確的引數被呼叫，以及它是否處理 gateway 的失敗？mock 驗證呼叫並可被設定為拋出——你無法讓真的 gateway 隨你指令失敗。對應：寫死 new → 物件接縫 → mock。 -->

## 修正 3 — 真實 `Date.now()` → 注入一個時鐘

```js
// 之前                       // 之後
const at = Date.now();       const at = deps.clock.now();
```

`Date.now()` 是**牆上時鐘**——每次執行都是一個全新的值，測試既無法預測也無法釘住。注入一個 `clock` 物件使它成為一道**物件接縫**：測試傳入一個凍結在已知時刻的時鐘。

- **接縫型別：** 物件接縫
- **可啟用（替身）：** **fake（假物件）**——一個 `now()` 回傳固定時間的可運作時鐘
- **解鎖能力：** *對固定的時間戳進行斷言*

儀表 → **3/4**。

<!-- 非決定性來源 #1：時鐘。一個讀取真實時間的測試永遠無法斷言一個確切的時間戳，所以它要嘛跳過檢查，要嘛做出像範圍斷言那樣脆弱的東西。一個 *fake* 時鐘是一個真實、可運作的物件（不只是現成回傳值），其行為可被控制——Date 釘在比方說 2026-01-01。fake 在此是正確的替身名稱，因為它是一個輕量的可運作實作，而非一個記錄器。對應：真實時鐘 → 物件接縫 → fake。 -->

## 修正 4 — 真實 `Math.random()` → 注入帶種子的 rng

```js
// 之前                                     // 之後
const id = Math.random().toString(36);     const id = deps.rng.id();
```

`Math.random()` 是第二個**非決定性來源**——每次執行都是不同的 id，所以測試無從得知 `charge()` 產生了什麼。注入一個帶種子的 `rng` 使它成為一道**物件接縫**：測試提供一個會產出已知序列的 rng。

- **接縫型別：** 物件接縫
- **可啟用（替身）：** **stub（樁）**——一個回傳固定、已知 id 的 rng
- **解鎖能力：** *讓產生的 id 具決定性*

儀表 → **4/4**。

<!-- 非決定性來源 #2：亂數。與時鐘同一套故事——單元裡的隨機性代表測試無法預測輸出。一個帶種子／被 stub 的 rng 回傳一個固定 id，於是產生的交易 id 現在可被斷言。替身是 *stub*（現成回傳值）而非 mock，因為測試只需要那個值，不需要驗證呼叫。時鐘是 fake、rng 是 stub，儘管兩者都移除了非決定性，這正好說明你伸手去拿的替身取決於測試需要做什麼。對應：真實亂數 → 物件接縫 → stub。 -->

## 接縫 → 替身對照

| 反樣式 | 接縫型別 | 可啟用（替身） | 解鎖能力 |
| --- | --- | --- | --- |
| 全域單例 `Config` | 物件接縫 | **stub** | 不動全域即可提供測試用的設定 |
| 寫死的 `new PaymentGateway()` | 物件接縫 | **mock** | 強制 gateway 失敗 |
| 真實時鐘 `Date.now()` | 物件接縫 | **fake** | 對固定的時間戳進行斷言 |
| 真實 `Math.random()` | 物件接縫 | **stub** | 讓產生的 id 具決定性 |

每一道接縫都是同一*種*——物件接縫——但每一道解鎖一個**不同的測試替身**，由那個測試需要做什麼來挑選。→ 在**測試替身**單元（第 #27 講）中*查看對應的測試替身*。

<!-- 這是探索器在右側渲染的對照表，也是本講的概念核心：一種接縫型別，四種不同的替身。忍住在這裡重新教 stub／mock／fake 的衝動——那是第 #27 講的工作，探索器刻意連結出去而非重新解釋。教學重點是那個*選擇*：接縫給你替換的能力；你放入哪一個替身是另一個決定，由你想做的斷言驅動（值 → stub、互動／失敗 → mock、可運作但受控 → fake）。 -->

## 為可測試性而設計 = 可替換的相依

這四個修正是同一個概念套用四次：**讓每一個相依都可被替換**。這就是為可測試性而設計*的本質*——不是寫更多測試，而是把程式碼塑造成讓測試能控制每一個輸入、觀察每一個輸出。

**可測試性儀表**衡量的正是這件事：`分數 = 已套用修正 / 4`。它不是一個程式碼品質的意見；它是這個單元真實世界相依中，測試現在能替換的比例。

在 **4/4** 時，`charge()` 是一個**近乎純粹的單元**：它的 config、gateway、時鐘與亂數全都透過 `deps` 抵達，於是測試驅動它們全部，並檢查剩下的那一行真正邏輯。

<!-- 落地這個論點：可測試性是一種設計性質，被刻意加上，而且可被度量。儀表（testabilityOf → applied.length / antipatterns.length）是決定性的且有單元測試，正是為了讓這一課精確，而非品味問題。「近乎純粹」是誠實的用詞——charge() 仍有一個副作用（gateway 呼叫），但每一個輸入現在都被注入，所以就測試的目的而言，它表現得像一個 deps + amount 的純函式。這與依賴注入框架所做的動作相同，只是徒手做並命名而已。 -->

## 工具演示 — 接縫探索器

在 `?explorer=testability-seams` 開啟搭配工具。

- **左欄**把 `charge()` 顯示為唯讀的註解程式碼，每個被釘死的相依有一個*套用接縫*開關，各自標有它的反樣式標籤。
- **套用一道接縫**，那一行就改寫為它注入後的 `deps.…` 形式，**可測試性**儀表往上爬，解鎖的能力出現在*測試現在能做到什麼*之下。
- **右欄**承載接縫／替身對照表，以及一個連向對應測試替身的連結。
- 套用全部四個，**收尾訊息**觸發：每一個相依現在都可被替換。

試著還原一個修正，看著儀表與它的能力消失——可測試性是可逆的，把一個相依釘回去所造成的損害也是。

## 小結

- **無法被測試的程式碼 = 寫死的相依。** 讀取全域、一個 `new`、真實時鐘、真實亂數，各自把一個真實世界相依釘進單元，使測試既無法控制輸入也無法觀察輸出。
- **接縫**（Feathers）是一個不在該處編輯就能改變行為的地方；**物件接縫**透過一個參數或欄位做到——那個啟用點就是測試交入替身之處。
- 這四個修正全是*同一道*接縫——**物件接縫**——但每一個解鎖一個*不同的***測試替身**：config → **stub**、gateway → **mock**、時鐘 → **fake**、rng → **stub**。
- 每一個修正解鎖一項具體**能力**：不動全域提供測試設定、強制 gateway 失敗、斷言固定時間戳、讓 id 具決定性。
- **為可測試性而設計 = 讓相依可被替換**；**可測試性儀表**以*已套用修正 / 4* 度量它，4/4 留下一個完全在測試掌控之下的近乎純粹單元。

**課堂練習：** 拿一個你自己、會呼叫時鐘、全域或 `new` 的函式。為每一個相依，點名能移除它的接縫與它會啟用的測試替身，接著寫下你做完之後變得可能的那一條斷言。
